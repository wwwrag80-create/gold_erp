# نظام محاسبي للذهب — تطبيق الجوال (أندرويد)

تطبيقٌ **للمندوب**: يأخذ البضاعة من **المصانع**، ويبيعها **للمحلات**، ويحصّل
منها ذهباً ونقداً، ثم يدفع للمصانع ما عليه.

- **الحسابات**: المحلات والمصانع، وكشف حساب كلٍّ منها، و«المبيعات والتحصيل»
  للمحلات (كشاشة العملاء في البرنامج).
- **مع المحلات**: فاتورة بيع، مرتجع، تحصيل (ذهب بعياره ونقد).
- **مع المصانع**: بضاعة من المصنع، إرجاع للمصنع، دفع للمصنع.
- **الممتلكات**: ما معي الآن — صندوقٌ لكل عيار (من التحصيل ناقصاً الدفع)،
  وصندوق النقد، والأطقم التي في يدي؛ ويُفصَّل كلٌّ منها: من مَن، وكم، ومتى.
- **سطر الطقم**: الطقم (اسمه اختياري) · العيار · الوزن · الأجر. وتفصيل الوزن
  (ذهب · أحجار · قائم · ماس) مطويٌّ لمن أراده. ويُختار الطقم الذي في اليد
  من «الطقوم التي معي» فيُعبَّأ وزنه.
- المعلّقات، مشاركة المستند صورةً أو PDF، والحفظ التلقائي في مجلد.

البيانات في الجوال وحده (IndexedDB داخل التطبيق) — لا سحابة.

## الفرق المقصود عن برنامج الكمبيوتر

- لا «وارد من التصنيع» ولا مخزون مصنع: الطقم يُباع ولو لم يُسجَّل قبلها.
- طقمٌ سبقت له حركة باسمه تُعبَّأ أوزانه منها (بيعٌ ← مرتجع، مرتجعٌ ← بيع،
  بضاعةٌ ← بيع أو إرجاع)، والأجر من الجهة نفسها لا من الأخرى.
- الأسماء الداخلية (`com.jadeite.mobile`، قاعدة `jadeite_mobile`، صيغة
  `jadeite-mobile-backup`) باقية كما هي: تغييرها يقطع التحديث فوق النسخة
  المثبّتة ويضيّع البيانات.

## المعادلات

`web/js/gold.js` منقولةٌ من `services/gold_math.py` و`services/karat_view.py`
بترتيب العمليات نفسه، و`web/js/num.js` يقرّب كما تقرّب بايثون حرفياً.
الفحص يقارن الاثنين على أكثر من مئة ألف حالة:

    python mobile/tests/parity_gen.py > /tmp/cases.json
    node mobile/tests/parity.js /tmp/cases.json
    node mobile/tests/domain.test.js
    node mobile/tests/e2e.js [مجلد_للصور]     # يحتاج playwright

## البناء والتوقيع

1. `.github/workflows/android.yml` يبني على GitHub ملفاً **غير موقّع**
   وينشره في الإصدار `mobile-unsigned`.
2. يُوقَّع خارج المستودع بمفتاح المالك:

       python mobile/tools/sign_apk.py --key DIR in.apk out.apk

   المفتاح (`DIR/key.pem` و`DIR/cert.der`) لا يدخل المستودع أبداً. والمفتاح
   نفسه في كل تحديث شرطٌ لتثبيت النسخة الجديدة فوق القديمة دون حذف بياناتها.

رقم الإصدار في `web/version.json` (يقرؤه البناء والتطبيق).

## التحديث (بلا سحابة المالك، ولا نشر داخل التطبيق)

- الملف الموقّع يُضاف إلى `mobile/dist/jadeite-mobile-<الإصدار>.apk` ويُسجَّل في
  `mobile/dist/versions.json` (`version`, `code`, `file`, `sha256`, `notes`).
  يُنزَّل من `raw.githubusercontent.com` — من GitHub لا من سحابة المالك.
- **القناة**: الصفحة (issue) رقم 23 في المستودع. في نصّها بعد
  `<!-- jadeite-mobile-channel -->` كتلة JSON بآخر إصدارٍ منشور (الرقم والبصمة
  والرابط). لا تُغلق ولا تُعدَّل يدوياً.
- **النشر**: من GitHub وحده — Actions ← «نشر تحديث الجوال» ← Run workflow
  (`.github/workflows/mobile-publish.yml` → `mobile/tools/publish_channel.py`).
  يتحقّق قبل النشر من بصمة الملف، واسم الحزمة ورقم الإصدار (aapt2)، وتوقيع
  المالك (apksigner)، ويرفض الرجوع إلى إصدارٍ أقدم؛ وفيه «تجربة فقط» بلا نشر.
  التطبيق نفسه بلا زرّ نشرٍ ولا مفتاح — نسخةٌ واحدة لكل المستخدمين.
- **المستخدمون**: يقرأ التطبيق القناة عند فتحه وكل 6 ساعات في الخلفية (والجهاز
  متصل)؛ فإن وجد أحدث نزّله، وتحقّق من بصمته، ونبّه بإشعار. التثبيت بلمسة
  (أندرويد لا يثبّت وحده)، والبيانات تبقى لأن المفتاح واحد.

## بقاء البيانات بعد حذف التطبيق

- **الحفظ التلقائي في مجلد** يختاره صاحب الجهاز (يفتح على Documents): بعد كل
  عملية يُكتب `gold-data.json` ونسخة اليوم `gold-data-YYYY-MM-DD.json`
  (تبقى آخر 14). بعد إعادة التثبيت تعرض شاشة الترحيب «عندي بيانات سابقة»
  فيُختار المجلد نفسه ويُسترجع كل شيء.
- **صور الأطقم** في مخزنٍ وحده داخل التطبيق، وفي المجلد ملفٌ لكل صورة
  (`gold-photos/<رقمها>.jpg`) يُكتب مرةً واحدة؛ وتُسترجع معه. ونسخة «الملف»
  اليدوية تحملها داخلها.
- **نسخ Google الاحتياطي** لأندرويد مفعّل أيضاً (يستثني مفتاح النشر وملفات
  التحديث المنزّلة).
