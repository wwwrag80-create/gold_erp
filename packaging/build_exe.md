# تحويل النظام إلى ملف تشغيل واحد (Windows exe)

```bash
pip install pyinstaller PyQt5 python-barcode qrcode Pillow
pyinstaller --onefile --windowed --name GoldERP main.py
```

- الناتج: `dist/GoldERP.exe`
- قاعدة البيانات `gold_erp.db` ومجلدا `backups/` و`assets/` تُنشأ تلقائياً
  بجوار ملف exe عند أول تشغيل (المسارات نسبية لمجلد التشغيل).
- لإضافة أيقونة: `--icon=assets/icon.ico`

## التحديث بزرّ «⬆ تحديث» في نسخة exe (4.55)

- الـexe ملفٌ واحد يحمل الكود في داخله، فحزمة التحديث (`.jup`) تُثبَّت في
  مجلد مستقل بجوار البيانات: `<مجلد البيانات>/app_code`
  (`D:/TreeSoft_System/Data/app_code` افتراضياً).
- عند كل تشغيل يقرأ الـexe ذلك المجلد قبل كوده المدمج **إن كان إصداره
  أحدث** (`code_overlay.py`)؛ وملف exe مبنيٌّ من كودٍ أحدث يتجاهله.
- قبل الاعتماد يفحص الـexe نفسه الحزمة: `gold_erp.exe --verify-code <مجلد>`
  (ترجمة كل ملف + استيراد كل وحدة بمكتبات الـexe). فإن فشل الفحص رُفض
  التحديث وبقي النظام على حاله.
- تحديثٌ يمنع الإقلاع يُعطَّل تلقائياً (يُعاد تسمية مجلده إلى
  `app_code_failed_…`) ويُعاد تشغيل الـexe بكوده المدمج.
- للتشخيص: `gold_erp.exe --about نتيجة.json` يكتب الإصدار الفعلي ومصدره.
- بناء الحزمة: `python tools/make_update.py <مجلد-الناتج>`.
- الـexe المبني قبل 4.55 لا يعرف هذه الطبقة: يُبنى مرةً واحدة من 4.55
  بـ`MAKE_EXE.bat`، ثم تُثبَّت التحديثات بالزر.
